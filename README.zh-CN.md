# VoxStage

**Mac 上离线运行的 AI 有声书制作与多角色配音工具。**把小说或剧本变成每个角色都有自己声音的朗读——有声书、视频配音旁白、广播剧、播客——全程在你自己的电脑上完成。免费开源。

**网站：<https://houjun.dev/voxstage/>**（英文）· *[English](README.md)*

面向 Apple Silicon Mac 的本地脚本配音工作台。把小说原文原样贴进去——一章、没有角色标注——得到一段多角色朗读：
可以逐句试听、修正、重做、导出，每一句都会被转写回来与原文核对，**原文保证不被改写**。

> **VoxStage 1.0。**整条流程——导入、角色复核、配音、生成、检查、编辑、导出、工程打包——已经完成，有 574 项自动测试覆盖。安装目前只在开发用的 Mac 上验证过；如果按[安装说明](docs/public/setup-zh.md)在你的 Mac 上装不起来，请提 issue。人工试听只覆盖了一部分——见[试听覆盖了什么](#试听覆盖了什么)。

## 能用来做什么

- **有声书**：小说、短篇或整本书，旁白加每个角色一个声音，一章一章做，导出 MP3 或 WAV，附字幕。
- **视频配音与旁白**：给 YouTube、讲解视频、纪录片、短视频配音；导出逐句字幕和可导入达芬奇（DaVinci Resolve）的剪辑时间线，每一句都在正确的位置。
- **广播剧与播客**：一份剧本排出一台广播剧或故事播客——多个角色、众人齐声，停顿和语速逐句可调。
- **课程与培训**：给课程、操作讲解配旁白；内容改了，只重新生成改动的那一句。
- **语言学习**：做中文或英文的听力材料，声音清晰稳定；可选的文字检查会标出读错的数字和多音字。
- **听自己的作品**：作者、编剧在交给编辑或演员之前，先听一遍稿子被各个角色念出来。
- **游戏与动画的临时配音**：给动态分镜、原型和提案先配上占位声音。
- **你自己的声音**：按描述设计新声线，或用你自己的录音克隆声线来朗读你的作品（软件里需要确认授权）。

## 素材和成品，始终留在你的电脑上

VoxStage 就是为不能、也不愿交给云服务的内容而做的：还没出版的书稿、客户的剧本、尚未发布的产品、你自己的声音。

- **从第一句到成品**：你贴进来的原文、设计或克隆的声线、每一版声音、所有修改、导出的音频，都存在你 Mac 上的一个文件夹里，任何一步都不上传。
- **本机 AI，不走云端接口**：配音和分角色的模型在你 Mac 自己的芯片上运行。装好之后不需要联网，启动器会让模型库保持离线。
- **没有账号，不回传数据**：不用注册，也不上报任何东西——没有使用数据、没有统计、没有崩溃报告。
- **不会因为使用本软件而泄露任何信息**：使用 VoxStage 不会把你的产品信息、未发布的内容或任何个人隐私暴露给我们或任何人。文件只在你自己决定时才分享出去。

## 它做什么

把小说原文照原样给它：

```
孔乙己一到店，所有喝酒的人便都看着他笑，有的叫道：“孔乙己，你脸上又添上新伤疤了！”他不回答，对柜里说：“温两碗酒，要一碟茴香豆。”便排出九文大钱。
```

本机模型先给每个单元标上旁白/对白并点出说话人，然后把草稿交给你修正——在下面的评测里多数场景都需要改，
所以**复核就是产品本身，不是走过场**。已经写成 `角色：台词` 的剧本会跳过草稿直接导入。之后给每个角色选一个声音，生成，
逐句工作——试听、重做、拆分、合并、定停顿——再导出。中文和英文目前都支持；超过一章的长文会整理成一本书，一章一章来。

产出：完整音频；按语音停顿切开、**按实际采样数**计时的字幕（SRT 与 VTT）；时间轴；给剪辑软件的逐句交付包和 FCP7 XML 时间线；以及内容核对报告。

## 为什么不直接用现成的 TTS 工具

六条特性，每一条都是刻意的设计取舍，不是功能堆砌：

**你的原文永远不会被改写。**分析和检查只能**标注**文本，只有你能改动它。朗读调整（数字、缩写怎么念）放在单独字段里，所以字幕保留你写的原话。

**改一句，只重做一句。**每个句段有稳定身份和生成指纹，指纹覆盖真正送给引擎的文本、声音和参数。改第 400 句里的第 40 句，其余 399 个音频文件原封不动——这是**比对字节和修改时间验证过的**，不是假设。

**生成的语音会被转写回来，与原文比对。**语音合成可能在听感完全自然的情况下漏字——[我们实测到一段文本被无声漏掉 17%](#这个产品是怎么来的)。所以成品音频会在本地转写，与应该说的话逐句比对。发现差异只做标记提示你去听，**绝不自动修改**。

**没有任何东西离开这台机器。**模型在本机 Apple Silicon 上运行。没有账号、没有云端生成、不按字数计费。剧本和参考声音留在你自己的文件里，不进版本库。

**活在你打开编辑器之前就该干完。**切句、判断谁在说话、把一本书的角色和别名从这一章带到下一章、把设置沿用下去——这些是程序的事；
目标是复核草稿只需确认、不需打字。程序没把握的地方用黄色说出来，完全不知道的用橙色，而且你在页面上每改一处它都跟着学。
本地模型不是把编辑工作推回给人的借口。

**模型是零件，不是产品。**分角色模型、语音引擎、识别器各自在一层接口后面，各有一个进指纹的身份标识，按哈希固定、在设置里选择；
分角色模型已经可以切换，第二个语音引擎或识别器应当以同样方式接进来，而不是写死在里面。

## 快速开始

在配置好的 Mac 上双击 **Start VoxStage.command**。用 **Check VoxStage.command** 查看环境报告，它不下载任何东西。

新的 Mac 请按 **[安装 VoxStage](docs/public/setup-zh.md)**：需要什么机器（Apple 芯片；小模型 16 GB，推荐 32 GB）、装哪些工具、按内存选哪些模型、怎么启动。界面有中文和英文，侧栏底部可以切换。装好后看[第一次试用](docs/public/quickstart-zh.md)：从一段小说到多角色录音。

## 三份完整样例

[《傲慢与偏见》第一章开头](examples/pride-and-prejudice-ch1/) —— 无标注的公版英文原文进去，
三个角色的音频和字幕出来，全程在一台 Mac 上跑完。分角色在 35 个切片里**只错一处**，
样例里写明了是哪一处、以及为什么那一类错误最危险。耗时、回读校验结果和已知限制都在那个目录里。

[一段专门写难的中文](examples/zh-hard-cases/) —— 反过来的做法：440 字里四个角色，
把分角色已知会错的情形全堆进去。它接住了此前两次都失败的尾随提示语，
却给同一个人起了两个名字——对合成来说，那意味着一个人用两种声音说话。

[鲁迅《孔乙己》](examples/kong-yiji/) —— 整篇小说，十分钟，一百年前的文字。
模型每次点名都点对了人，却仍需要 43 处修正：它把「掌柜说：」这类四个字的叙述当成了台词。
引擎读不出两个 1938 年版的字形；时长检查抓住了一句 12 个字念了 13 秒的失败；
回读检查则学会了不能指望识别器认识人物的名字；五个声音里有三个——包括旁白——是本人听过所有预设都不合适之后，
用一句话描述设计出来的。

## 试听覆盖了什么

**同一角色跨句音色一致性于 2026-09-10 通过试听。**中英各六句连续旁白，每段约 32 秒，每句只生成一次、固定种子、不挑版本；
本人判断两种语言的音色、空间感、发音与完整性都一致。前一天同一标准曾在两句上未通过——那条记录和这次通过及其范围一起留在
[`acceptance.md`](docs/public/acceptance.md) 里：只测了两个预设，不含重做、不超过 32 秒、没换种子。「角色到第 300 句还是同一个人」**没有宣称**。

**没有试听过的：**已发布的《孔乙己》样例没有逐句听过——声音是本人听着选的、确认了一句，其余只做了机器检查；1.7B 模型除本人 2026-09-13 对比过的那几句之外。文件存在不等于通过。

## 这个产品是怎么来的

VoxStage 源于一次本地模型研究中发现的具体故障：一段声音克隆自然、可辨认地读完了全文，却**无声地跳过了中间 40 个字**。没有人能听出来——因为跳过之后读出的仍是一句通顺的话。

两条设计规则由此直接得出，并且都在产品里：

- **逐句生成。**跳句发生在长文本一次性生成；短句段同时带来逐句缓存和字幕时间粒度。
- **转写回读比对。**静默失败无法靠试听发现，只有一个**能与结果唱反调**的检查才找得到它。

完整记录：[AI-Lab / 声音克隆核验](https://github.com/hera2019/AI-Lab/blob/main/qwen3-tts-0.6b-voice-clone-mlx/results/phase-1-iphone-repeat-verification.md)

## 自动分角色：先测过，再作为草稿上了产品

对没有标注的小说文本，本地模型可以提出谁在说话。在 20 个自写中英文场景上比较了两个本地模型，流程中**原文由程序恢复，不由模型抄写**：

| | Qwen3 4B Q8 | Qwen2.5 1.5B Q4 |
|---|---:|---:|
| 原文完整保留（程序保证） | 20/20 | 20/20 |
| 明确对白角色正确 | 34/40 | 15/40 |
| 歧义对白正确标为 UNKNOWN | 4/4 | 1/4 |
| **整个场景全部标签正确** | **8/20** | 1/20 |

**最后一行才是决定产品形态的那个数字。约 60% 的场景需要人工修改**，所以自动分角色只能作为**可编辑的草稿**交给人审核，绝不做无人值守的批量生成。20/20 的原文保留是程序规则的功劳，不是模型的。

参考答案由助手在模型运行前拟定，尚未经独立人工复核；20 个场景中有 16 个在更早的基线里出现过。**这是用于工程选型的证据，不是泛化能力的结论。**
之后草稿接进了产品，模型之上加了程序规则，规则的数字在上面的表里。提示词现在要模型对每句给出最可能的说话人并说明原文是否能定；
定不了的名字在复核页以黄色预填出现；模型完全认不出的句子，会按这个角色在已确认章节里的说话习惯来填。
同样 20 个场景上，这套提示能点对 33–34/40 个明确说话人；多出来的类型错误全是不带引号的单元，引号规则会修正。

语料、提示词与评分：[`evals/speaker_attribution/`](evals/speaker_attribution/) · 结果：[`results/speaker-attribution-summary.md`](results/speaker-attribution-summary.md)

## 限制

- 角色草稿只是草稿。评测里多数场景至少要改一处，复核这一步跳不过去。一章按机器内存分批处理（16 / 32 / 64 GB 的 Mac 每批 3000 / 6000 / 12000 字），比一章长的文本先切成章。
- 九个预设音色，其中英文只有两个且都是男声。音色库打破了这个上限：把满意的那一版存成具名音色，或者在确认拥有使用权后提供自己的录音。无论哪种，参考声音都只留在本机、不进版本库，而提供的录音绝不会被标成合成语音。
- 字幕使用基于能量的语音边界估计，需要人工复核，**不是强制对齐**。
- 峰值归一化，不是响度标准合规。
- 取消在句间生效，当前正在生成的句子会完成。
- 安装只在开发用的 Mac（M2 Max，32 GB）上验证过；在全新 Mac 上完整安装、Homebrew 版的 llama.cpp 与 whisper.cpp 都还没验证。
- 仅限 Mac，没有安装包签名和自动更新。服务默认只在本机监听；用 `--lan` 启动才向局域网开放，每台设备输入一次访问口令。手机在普通 HTTP 下不能录音，改为上传录音文件。
- 内容核对忽略普通标点和大小写，但保留否定、数字和有意义的符号。同音字和数字读法差异会造成误报。**不宣称任何准确率**——没有测过。

## 伦理

- 固定角色声线由模型自己的合成输出构建，保存时带校验和与生成它的文本。你自己提供的录音，只有在你确认拥有使用权之后才会被接受——这道门槛写在音色库代码里，不只是屏幕上的一个勾选框——保存时标为 `synthetic_audio: false`、`consent_confirmed: true`，只留在本机、不进版本库。
- 生成音频不冒充真人。
- 你提供的剧本，其内容权利由你自己负责。

**使用规范（Responsible Use）**：请遵守当地法律并尊重他人的隐私与肖像权。不得将本工具用于制作涉及未成年人的色情内容、未经本人同意的私密或色情影像、欺诈性冒充、骚扰、勒索或其他违法用途。用户对自己使用模型和生成内容的方式负责。
